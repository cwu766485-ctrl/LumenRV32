# JTAG DMI Clock-Domain Crossing

## Scope

`jtag_TCK` is generated by an external debugger and has no defined phase or frequency relationship to `cpu_clk`. DMI requests and responses therefore cross clock domains in both directions.

This note covers the DMI bridge between `jtag_driver` in the TCK domain and `jtag_dm` in the CPU domain. The CPU-focused FPGA profile ties `jtag_TCK` low; that build is not active-TCK board validation.

## Design

```text
TCK domain (jtag_driver)                         CPU domain (jtag_dm)
DMI request bundle + four-phase req/ack   -->    DMI request receiver
DMI response receiver                    <--    DMI response bundle + four-phase req/ack
```

`full_handshake_tx` holds its source bundle stable until acknowledgement. `full_handshake_rx` uses a two-flop synchronizer only on the single-bit request control, then captures the stable bundle. The acknowledgement return path is synchronized in the same way. The synchronizer flops carry `ASYNC_REG` attributes to preserve their CDC intent during implementation.

`jtag_cdc_reset_sync` provides asynchronous reset assertion and two-local-clock release in each domain. This avoids treating reset deassertion as an unverified asynchronous event.

This is a bundled-data four-phase handshake. Synchronizing each DMI data bit independently would permit torn data and is intentionally not used.

## Verification

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\run_jtag_dmi_cdc_tb.ps1
```

The testbench uses a 100 MHz CPU clock, an approximately 58.8 MHz phase-offset TCK, and an intentionally unaligned reset release. It transfers four 40-bit DMI requests and responses, checking for loss, duplication, and data corruption.

Fresh result on 2026-08-23: `JTAG_DMI_CDC_TB_PASS`. The complete `simple` SoC smoke also returned `TEST_PASS` after this change.

## Constraints and limits

`fpga/zu15eg_cpu_jtag_raw_top.v` is the board wrapper for a raw four-wire PL JTAG connection. It exposes `jtag_TCK/TMS/TDI/TDO` and reuses the hardened DMI CDC. `tools/build_zu15eg_cpu_jtag_raw.ps1` requires `-JtagXdc`, a real FMC/PMOD/GPIO pin and I/O-standard mapping; the repository intentionally provides only a pin-free example.

The profile base XDC constrains external TCK initially at 50 MHz and declares it asynchronous to `PL_REFCLK_200M` and derived CPU clocks. The data bundle must not be blanket false-pathed; after synthesis, a flow may add datapath-only/max-delay checks using actual register instance names.

This work is RTL hardening with asynchronous-clock simulation evidence. It is not static CDC sign-off, active-TCK FPGA post-route closure, or board-level JTAG acceptance. The board USB-JTAG configuration chain cannot be wired directly to this raw TAP; using that path requires a separate BSCANE3 user-scan adapter.
